# i18n 契约：多语言翻译格式规范

**版本**: 1.0
**适用范围**: 所有前端运行形式（Chrome 扩展、网站、PWA、Webview）

---

## 文件格式

遵循 Chrome Extension i18n 规范：`_locales/{chromeLocale}/messages.json`

### 单个消息文件结构

```json
{
  "messageKey": {
    "message": "翻译文本",
    "description": "可选：面向翻译人员的上下文说明"
  }
}
```

### 完整文件示例（`_locales/zh_CN/messages.json` 节选）

```json
{
  "siteName": {
    "message": "ImgTune",
    "description": "应用名称，通常不翻译"
  },
  "siteTagline": {
    "message": "免费在线图片格式转换与处理工具",
    "description": "网站副标题，显示在 Header 下方"
  },
  "convertButton": {
    "message": "开始转换",
    "description": "图片转换提交按钮文字"
  }
}
```

## 前端访问接口

前端通过 `i18n/adapter.ts` 统一访问翻译，屏蔽环境差异：

```typescript
// 公开接口
export function getMessage(key: MessageKey): string;
export async function loadMessages(locale: AppLocale): Promise<void>;
```

### 访问策略

| 运行环境 | 底层实现 | 备注 |
| --------- | --------- | ------ |
| Chrome 扩展 | `chrome.i18n.getMessage(key)` | 原生 API，自动根据浏览器语言选择 locale |
| 网站 / PWA / Webview | `fetch('/_locales/{chromeLocale}/messages.json')` | 运行时加载，`en` 作为内联 fallback |

### Chrome 扩展 manifest 引用语法

在 `extension/manifest.json` 中，消息键通过 `__MSG_key__` 语法引用：

```json
{
  "name": "__MSG_siteName__",
  "description": "__MSG_siteDescription__"
}
```

## 语言检测策略

| 优先级 | 检测方式 | 说明 |
| -------- | --------- | ------ |
| 1 | `chrome.i18n.getUILanguage()`（扩展环境） | Chrome 浏览器界面语言 |
| 2 | localStorage `imgtune-locale` | 用户上次选择的语言，手动持久化 |
| 3 | `navigator.language` | 浏览器首选语言 |
| 4 | `en`（最终 fallback） | 保证始终有语言可用 |

**语言代码规范化**: `navigator.language` 返回如 `zh-CN`、`de-DE`，需映射到最接近的 AppLocale（`zh-CN` → `zh`，`de-DE` → `de-DE`）。

## 迁移说明

从现有 `src/locales/*.json`（flat 格式）迁移到 `_locales/*/messages.json`（嵌套格式）的步骤：

1. 创建 `_locales/` 目录结构（8 个语言子目录）
2. 将每个文件中 `"key": "value"` 转换为 `"key": { "message": "value" }`
3. 为常用键添加 `description` 字段（可选，改善翻译协作）
4. 按照语言代码映射表重命名目录（如 `zh.json` → `_locales/zh_CN/messages.json`）
5. 删除旧的 `src/locales/` 目录
6. 更新 `src/client/i18n/adapter.ts` 不再 `import` 静态 JSON，改为运行时加载
